# 引擎参数扫描（20 个样本，用归档里的原始截图）

方法：对 `tests/evidence/20261003-171722/images/NN-default-try1-raw.png`（`--keep-image` 存下来的原始像素）
逐张跑 Tesseract，参数见 `commands.txt`，逐字比对（去空白）。**不驱动窗口，所以可复现、不依赖桌面状态。**

| 参数 | 逐字正确 | 允许 1 字误差（≈） |
| --- | --- | --- |
| `--psm 6`（KeyMouse 当前默认） | **12/20** | 16/20 |
| `--psm 7`（单行） | 12/20 | 16/20 |
| `--psm 11`（稀疏） | 11/20 | 15/20 |
| `--psm 6 --dpi 96` | 12/20 | 16/20 |
| `--psm 6` + 标准模型（tessdata-std） | **10/20** | 15/20 |
| `--psm 6 --user-words <UI 词表>` | 12/20 | 16/20 |

## 结论

**这批语料上，引擎自己的旋钮一个都没买到东西**：psm 换 7 不变、换 11 更差、加 DPI 提示不变、
换标准模型更差（10/20）、给 UI 词表不变（LSTM 模型基本不吃 dawg 词典）。

真正能动数字的是另外两件事（都由同一批留档算出）：

1. **图片预处理**：`--scale 3 --pad 16 --normalize` 是 14~15/20，比原始像素的 11~12/20 高 3 个样本。
2. **允许 1 个字符误差**：12~15/20 → **17/20**（用真正的编辑距离算的最小值）。
   失败的样本里，绝大多数最小编辑距离就是 1（`保存按钮`→`保存近钮`、`按钮`→`控钮` 这种）。

## 误差棒（别过度解读）

20 个样本、单一字体（Consolas 12pt）、单一主题：比例的标准误约 ±11%。
所以"12 vs 15"这种差距还不能定论；要定论得先把语料扩到多字体/多字号/深色主题/中英混排。
