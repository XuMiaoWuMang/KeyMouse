# check-input.ps1 —— 这个会话收不收得到注入的输入

[check-input.ps1](../../tools/dev/check-input.ps1) 用一个结论明确的实验回答一个问题：**在这台机器的这个会话里，KeyMouse 打进窗口的字真的进去了吗？**

桌面冒烟的每一条断言都建立在"注入真的落地"上。可有些环境里 `SendInput` **报告成功、事件却被丢掉**：嵌套/沙箱会话、远程桌面窗口被挂在后台、前台有输入法候选窗或安全软件在拦。那种情况下冒烟会一口气红几十项，根因却只有一个。这个脚本把"会话收不到输入"和"产品坏了"这两种完全不同的处境分开。

## 用法

```pwsh
pwsh tools\dev\check-input.ps1                          # 用 artifacts\cli\KeyMouse.exe
pwsh tools\dev\check-input.ps1 -Exe path\to\KeyMouse.exe
pwsh tools\dev\check-input.ps1 -KeepOpen                # 冒烟靶子留着不退，看现场
```

| 参数 | 说明 |
| --- | --- |
| `-Exe` | 被测的命令行，默认 `artifacts\cli\KeyMouse.exe` |
| `-TargetExe` | 靶子程序，默认 `tests\KeyMouse.SmokeTarget\bin\Release\net10.0-windows\...` |
| `-KeepOpen` | 结束时留着冒烟靶子不杀 |

## 它做了什么

1. 杀掉残留的冒烟靶子，重新起一个。
2. `window focus` 把靶子拉到前台（注入落到哪个窗口，取决于那一刻谁是前台）。
3. 剪贴板里放一个哨兵串 `km-clipboard-sentinel-5193`。
4. 用 KeyMouse 打一串固定字 `km-inject-5193`，再 `Ctrl+A`、`Ctrl+C`。
5. 读回剪贴板：**正好是那串字**才算注入可用。

第一次失败后会再试一次：**先按两次 `Shift`（切到英文输入）再打**。中文输入法在位时，注入的字符会先进候选窗而不落进文档，连按两次 Shift 切到英文就能打出来。这一步会改动这台机器的输入法状态，所以只在第一次失败之后才做；成功时会明确告诉你"需要先把输入法切到英文"。

固定串是故意的：现场一看就知道读到的是它、还是哨兵。

## 退出码

| 退出码 | 含义 | 该怎么办 |
| --- | --- | --- |
| 0 | 注入可用（输出里会说明是否要先切英文输入） | 放心跑冒烟；提示要切英文就先按两次 Shift |
| 3 | 注入不可用（两次都收不到） | 换一个真正交互的终端再试；仍旧如此才是产品问题 |
| 4 | 环境没准备好（找不到 exe 或靶子） | 先 `.\km ba` 与 `pwsh tools\build\build.ps1` |

## 谁在用它

- [verify.ps1](verify.md) 在跑冒烟之前调用它：返回 3 就把冒烟这一关记为"已跳过"并写明原因，而不是染红一片。
- [桌面冒烟](../tools/smoke.md) 自己在开头也调用它（返回 3 直接停，退出码 3）；已知会话正常时可加 `-SkipInputCheck` 省掉这两秒。

## 读不到输入时会看到什么

日志会照实打印"期望"与"实际"：

```
输入注入不可用：KeyMouse 报告已发送，但靶子里什么也没收到。
  期望剪贴板：km-inject-5193
  实际读到：  'km-clipboard-sentinel-5193'
```

哨兵还在，说明 `Ctrl+A`/`Ctrl+C` 也没到达窗口——不是"打了字但复制失败"，是被注入的事件从头到尾都没被这个会话接收。

## 注意

- 会临时改剪贴板，结束时还原。
- 不落任何产物：没有运行目录，失败也不留文件（要看现场就加 `-KeepOpen`）。
- 它**不判断**产品逻辑对不对；只回答"注入在这台会话里能不能生效"。
