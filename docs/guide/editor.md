# 用编辑器完成一次自动化任务

打开安装版编辑器或[从源码启动](../dev/development.md)。先试着打开[计数示例](../../samples/demo-flow.json)，选中最后一个断言，查看条件 `count == 2`。这条流程可以直接播放，不读屏也不发送键鼠输入。

## 从录制到可重复的流程

| 菜单选项 | 记录什么 | 适合什么任务 |
| --- | --- | --- |
| 关键录制（编辑器默认） | 点击、滚动、拖动、输入和快捷键，跳过空移；每步默认等 1000 ms | 完成操作即可，不要求复刻节奏 |
| 完全录制 | 保留抽稀后的移动和实际间隔 | 悬停展开、轨迹或节奏会影响结果 |

点击录制，确认后在目标窗口操作；按 `Ctrl+Alt+Q`，或在 0.3 秒内连按两次 Esc 停止。录制不会自动在开头插入「切换窗口」。如果任务从特定窗口开始，可显式添加 `focus`。

选中动作，修改右侧的「执行前等待（毫秒）」。它从上一步结束起算，首步从启动起算。填 `0` 立即执行；留空默认 1000 ms。旧录制保留 `atMs` 的原节奏，填写等待可覆盖该步。拖动、长按和打字本身的耗时与执行前等待分开。等待页面加载时，优先使用「等待窗口」或「等待文字」，不要仅靠延长时间猜测。

## 指定操作对象

取点时检查坐标空间：**客户区**跟随目标窗口，**屏幕**以桌面为参照。编辑器优先将窗口客户区内的鼠标动作记为后台步骤；桌面、标题栏和跨窗口拖动不保证能这样记录。回放要求目标唯一且满足权限检查，不满足时不会悄悄改成点前台。普通键盘输入仍需正确的前台窗口。

## 编辑与验证

在画布添加步骤或展开分支，选中节点可编辑参数。`call` 引用独立的子流程文件；保存父流程不应被当作保存所有子文件。先「试运行」检查参数和目标，再「播放」。试运行不发送输入，也不能证明业务界面真的收到点击。失败时从日志的步骤编号和退出码定位，再看[排障指南](troubleshooting.md)。

截图用于判断当时点在哪里，不是播放所需的凭据。另存或分享流程前检查 JSON 和同名 `.shots/`；导出日志时也请先[脱敏](publication.md)。
