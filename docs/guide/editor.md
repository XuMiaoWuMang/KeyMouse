# 流程编辑器

KeyMouse 流程编辑器（`KeyMouse.FlowEditor.exe`）是 WinUI 3 写的图形前端：把一条流程（一串"切窗口 / 点一下 / 打字 / 等某段字出现"的动作）**看着改、试着跑**，而不是手写 JSON。
它只负责编辑与观察——录制、取区域、读屏、回放都在命令行那边，编辑器通过常驻的 Runner 调它们（连不上就是这种情况，见[故障排查](troubleshooting.md)）。

装在哪、怎么装见[安装、升级与卸载](install.md)；流程 JSON 的字段契约见[流程契约](../reference/interface.md)。

## 打开它

三种入口：

- 开始菜单 → **KeyMouse 流程编辑器**（安装版才有；启动会弹一次 UAC，原因见下面「开发版与发布版」）；
- 命令行：`KeyMouse flow edit 流程.json`，直接把这份文件打开；
- 已经打开了：起始面上有「新建流程」（Ctrl+N）、「打开流程…」和「最近」（最多 5 条，记在 `%LOCALAPPDATA%\KeyMouse\editor.json`）。

没打开任何文件时，起始面写着「还没有打开流程」，并提示可以先在命令行跑 `KeyMouse record` 录一段，再回来打开它写出的 JSON。

## 界面：两栏，加一条底线

窗口从上到下是四段。**没有画布，也没有时间线**——一条流程就是一列按顺序执行的步骤，编辑它就是在这一列上增删改。

| 位置 | 是什么 |
| --- | --- |
| 顶栏 | 左：`KeyMouse` + `流程编辑器`；中：文件路径（未保存时显示「还没有保存到文件」）；右：未保存的朱砂点 `●` |
| 工具栏 | 左边固定四个常用步骤按钮 + 「更多」；右边：`暂停`、`停止`（只在运行时出现）、`录制`、`试运行`、`播放`（F5）、`文件` 菜单 |
| 左栏 | 步骤列表：一行一步，带编号、图标、类型名与一行摘要 |
| 右栏 | 参数检视器：当前选中那一步的全部字段，外加「JSON」折叠板 |
| 底部 | 运行输出：消息与日志，运行时会自动展开 |

左栏的行：编号是**显示顺序**（不是文件下标）；有子步骤的步骤（重复 N 次 / 遍历列表）行右侧带展开箭头和子步骤数，点父行展开、再点收起，子步骤按缩进排；右键一行有「复制这一步 / 删除这一步 / 上移 / 下移」。跑完一步，结果（✓ 用时、✗ 原因）直接写在那一行右侧，不另开表格；录制出来的步骤带缩略图，点它用系统看图工具打开截图。

底部「运行输出」是整份界面的消息去处：常规消息、警告、错误都写成以 `# 提示` / `# 注意` / `# 错误` 开头的一行加缩进说明。它自己会展开（占窗口三成高，约 140–260 像素），拖它上方的分隔条能改高度；拖到底或收起来之后，右下角会留一个「输出」按钮把它叫回来（不然拖没了就只能重启）。面板右上角那个图标按钮是清空（提示「清空输出」）。日志留最近 900 行或 40 万字符。

## 加一步

工具栏左边那四个按钮是最常用的四种步骤，按钮上就是它们的短名：**点击**、**输入文字**、**等文字出现**、**找字并点它**；鼠标停上去的一句话提示来自契约（`flow.schema.json` 里这一类型自己的摘要），不在这里另写一份。

别的类型走「更多」（快捷键 `Ctrl+Shift+A`）：面板按用途分四组——**窗口**（切换窗口、等窗口出现）、**输入**（点击、鼠标长按、键盘长按、输入文字、按键/组合键、拖拽、移动、滚轮）、**看屏幕**（等文字出现、找字并点它、读进变量）、**流程**（等待时间、重复 N 次、遍历列表、调用子流程）。点一项就加一步；面板不会自己关，可以连着加几步，点面板外面才收起。

新加的那一步落在**选中那一步之后**；选中的是分组行（`repeat` / `foreach`）时落进这个组里；什么都没选就加到末尾。

## 改一步：参数检视器

检视器里的每一格都从契约 `flow.schema.json` 生成：契约里没有的字段，界面上不会凭空多出来。三条读法：

- **默认值**直接显示在输入框里（灰色占位），留空就是不写这个参数；
- 字段名右边的 ⓘ 是这一格的说明；标「必填」的字段没填，错误文字会出现在输入框**下方**（不会只闪一下）；
- 取值受限的字段是下拉（枚举的第一项「（默认）」= 不写），数字字段带范围。

有些字段可以用鼠标在屏幕上"指"出来：点/区域字段下面有「从屏幕取一点…」和「从屏幕取一块…」两颗按钮，和文件菜单里的「从屏幕取区域…」是同一套浮层（见下一节）。

检视器最下面「JSON」展开后是这个步骤在文件里的真实内容（只读），排查"界面以为改了、文件里没改"时看它。

**前提（`when`）**：检视器里有一个开关「满足才执行」——打开后先读一次屏幕，读到指定文字才执行这一步；关掉就等于没有前提，不会留半截字段。「前提要读的窗口与区域（默认就是这一步的）」默认收起，需要盯别的窗口时才展开。

## 从屏幕取点、取区域

- **取区域**：浮层上拖出一个框；单击则选整个客户区；`ESC` 取消。
- **取点**：在屏幕上点一下就结束；`ESC` 或右键取消。

选完有两件事同时发生：坐标写进当前字段，窗口的 `process` / `class` / `title` 顺手填进这一步的 `target`（只对本来就有目标窗口的步骤这么做）。写进文件的区域一律是**目标窗口客户区**相对坐标；取点只有在"这一步没有目标窗口、就发到这个屏幕位置"时才写屏幕坐标。

取消不会改动任何东西——底部只会多一句「取消了，没有改动。」。

## 录制

点「录制」→ 一个确认框（会真开始录，还可能丢弃未保存的改动，所以它必须问）→ 编辑器窗口隐藏，屏幕右侧出现一个红点，操作照常做。

停止有两条路：按 **Ctrl+Alt+Q**（录制进程的全局热键），或点屏幕上那个红点。停止后编辑器窗口自己回来，流程读进编辑器。红点万一没起来（它是原生窗口，只在录制时才创建），编辑器就不藏窗口，直接点工具栏已经变成「停止录制」的那个按钮收尾。

要点：

- 录到的流程先落在临时目录的 `keymouse-record.json`（默认 `%TEMP%`，不可写时退到备用目录，见 `KeyMouse doctor`），读进编辑器后算「未命名」——想留住它得自己 `Ctrl+S` 或另存为；
- 录制期间窗口是藏起来的，看不见按钮是正常的，用红点或热键结束；
- 一步都没录到时会明说没有产生流程文件，而不是给你一个空文档。

## 试运行与播放

两个按钮的差别只有一条：

- **试运行**：只做资格检查（窗口在不在、最小化没有、区域能不能用），**不发送任何输入**，也不存截图；
- **播放**（F5）：真的发。

跑之前编辑器先保证"跑的就是你看到的"：文件已经存过、也没有未保存改动，就直接跑那个文件；否则把你的当前内容写进临时目录的 `keymouse-editor-run.json` 再跑——未保存的改动照样生效，又不会覆盖你正在编辑的正式文件。运行时工具栏上出现「暂停」和「停止」（停止 = 取消，取消点之后不再发输入），日志一行行刷进底部。

跑完底部会出现一条结论：`N 步全部成功…退出码 0：整条流程都成功了。`，或者「第 K 步「某动作」失败。前面几步成功。」；非 0 时结论条里亮出「选中失败的那一步」——点它跳到失败那行。退出码含义与命令行完全一致：

| 退出码 | 意思 | 能不能直接重跑 |
| --- | --- | --- |
| 0 | 成功 | — |
| 1 | 运行时失败（例如 `SendInput` 被 UIPI 拦截） | 先解决权限/被拦的原因 |
| 2 | 参数错误、流程本身不合法 | 改流程 |
| 3 | 没等到、没匹配上，或选区被取消 | 可以（没发任何输入） |
| 4 | 目标窗口不可用（最小化、被遮盖、无响应） | 可以（没发任何输入） |
| 5 | 焦点没验证通过 | 可以（没发任何输入） |
| 6 | 没读到内容（区域不对、引擎看不懂） | 可以（没发任何输入） |
| 7 | 被取消 | 可以（取消点之后没发输入） |

## 保存、另存

`Ctrl+S` 保存，`Ctrl+Shift+S` 另存为，`Ctrl+O` 打开；都在「文件」菜单里。标题栏右侧的 `●` 一出现就表示有未保存改动。

保存前会先校验必填项：缺东西时底部会说「第 N 步有 M 处必填项没填，已在对应字段下方标出。」——先在检视器里把这些格子填了。直接点「试运行」/「播放」不会先拦你：引擎会以退出码 2（流程不合法）或某一步失败的形式告诉你哪里不对。

## 什么会打断你

只有**会丢东西**的动作才弹对话框（`ContentDialog`），其余反馈一律走底部那条消息带，不遮画面：

| 时机 | 对话框 |
| --- | --- |
| 关闭窗口、新建、打开别的文件，而当前流程有未保存改动 | 「有未保存的改动 / 关掉之前要保存吗？」或「…前先保存吗？」，按钮 保存 / 不保存 / 取消 |
| 开始录制 | 「开始录制」，说明停止方式，按钮 继续录制 / 取消 |

「更多」的步骤选择面板是浮层（点外面关闭），不是对话框。

## 崩溃了去哪看

编辑器把三类未处理异常都写进同一个文件：`%LOCALAPPDATA%\KeyMouse\editor-crash.log`，一行时间戳加一行异常，作用域写着「UI 线程」「非 UI 线程」或「未观察的 Task」。UI 线程的异常被记下后**程序继续跑**（不弹窗、不退），所以"刚才那下没反应"先翻这个文件。

## 开发版与发布版

标题栏写着身份，一眼能分清手上这份是什么：

```
KeyMouse 流程编辑器 0.2.1（构建 10-26 21:33 · 管理员）
```

- **构建时间**是这个 exe 的写入时间，用来区分"刚编的"和"上周装的"；
- **管理员 / 普通权限**是启动时的身份。编辑器带 `requireAdministrator`，**启动即提权**——不提权就录不到、也点不动以管理员身份运行的程序。开发构建走的是同一份清单，所以开发时也是「管理员」；
- 只是调界面、不想每次弹 UAC（或者想让普通权限的 `KeyMouse` 去点它），用 `pwsh tools\dev\km.ps1 e -NoElevate` 编一份普通权限的，标题会显示「普通权限」；
- 提权的副作用：系统文件选择器在提权进程里会失败，编辑器改用经典对话框，用起来没差别；
- 两种形态都通过 `ProductLayout` 统一找命令行，所以开发树里**没有** `cli\` 文件夹是正常的——完整顺序见[开发树与安装版](environments.md)。

用普通权限的开发版验证界面改动、用发布版验证"真能录到管理员窗口"，是仓库里一直沿用的分工；怎么编译与打包见[开发与发布流程](../dev/development.md)。
