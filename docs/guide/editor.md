# 流程编辑器

KeyMouse 流程编辑器是一屏图形前端：把一条流程（一串"切窗口 / 点一下 / 打字 / 等某段字出现"的动作）**看着改、试着跑**，而不是手写 JSON。

安装包里有两个 exe，界面上是同一屏：

| 文件 | 是什么 | 权限 |
| --- | --- | --- |
| `KeyMouse.Editor.exe` | 新外壳（Tauri + Svelte），开始菜单快捷方式指向它 | 普通权限（界面不提权） |
| `KeyMouse.FlowEditor.exe` | 老外壳（WinUI 3），过渡期保留；`KeyMouse flow edit` 默认开的是新外壳，找不到它才退到老外壳 | 启动时提权 |

新外壳需要系统的 WebView2 运行时（Windows 11 自带；缺了怎么办见[故障排查](troubleshooting.md)）。除权限与启动方式外，两边能做的事相同，本文的描述对两者都适用。
它只负责编辑与观察——录制、取区域、读屏、回放都在命令行那边。新外壳**不用常驻 Runner**：每次试运行/播放都拉起一次 `KeyMouse.exe`，读它的输出与报告（见[编辑器 IPC 契约](../reference/editor-ipc.md)），所以"编辑器能不能跑"和"命令行能不能跑"是同一件事。

装在哪、怎么装见[安装、升级与卸载](install.md)；流程 JSON 的字段契约见[流程契约](../reference/interface.md)。

## 打开它

三种入口：

- 开始菜单 → **KeyMouse 流程编辑器**（安装版才有；打开的是新外壳，不弹 UAC。老外壳 `KeyMouse.FlowEditor.exe` 启动会提权，原因见下面「开发版与发布版」）；
- 命令行：`KeyMouse flow edit 流程.json`，直接把这份文件打开；
- 已经打开了：起始面上有「新建流程」（Ctrl+N）、「打开流程…」和「最近」（存 8 条、显示 5 条，记在 `%LOCALAPPDATA%\KeyMouse\editor-settings.json`）。

没打开任何文件时，起始面写着「还没有打开流程」，并提示可以先在命令行跑 `KeyMouse record` 录一段，再回来打开它写出的 JSON。

播放前会先查一遍必填项：哪一步还缺东西（比如「输入文字」没填文字），底部会直接点名并选中那一行，
而不是等命令行跑到一半才报错。想看细节就用 Ctrl+Enter 试运行。

## 流程长了怎么看

画布默认是**自由布局**：每个节点都可以拖到任意位置，拖动块时整棵子步骤跟着走，连线从节点边缘重新计算。节点可以拖到画布左边界以外（负坐标区），不会再被一条看不见的墙挡住。箭头不是装饰——它按执行语义画：`if` 有「成立」和「否则」两个出口；循环体最后一步同时有「返回」回到循环开头、和「退出」去下一步；`break` 只画「跳出」，`continue` 只画「继续」。节点拖得再乱，箭头方向仍由流程树决定。

连线是**直角折线**，像 drawio 一样转弯，不再用会被节点盖住的曲线。出边/入边按两个节点的位置自动挑边：中心连线和纵轴的夹角小于 45° 时走上下边，否则走左右边；折线会绕开其它节点。两个节点左右分开时，左边节点从右边出、进右边节点的左边，反向同理，不会在中间绕一个结。

**点一下任意连线**可以选中它，选中后两端会出现圆点；把圆点拖到节点四条边的任意位置，就能固定这条线的起点/终点，直线和折线会从新接口重新绕行。双击连线恢复自动接口。手工接口按文件存在本机（`localStorage` 的 `keymouse.ports.v1:<文件路径>`），不写进流程 JSON；换机器或把文件发给别人不影响流程，只是接口回到自动选择。

选中单个节点时，节点四条边会出现四个淡蓝箭头，这是**快速添加入口**：上/左是「在前面插入一步」，下/右是「在后面加一步」。它和工具栏的「＋ 添加」打开同一个面板，但会记住插入位置；点面板里的类型后直接插成同父同分支的兄弟节点，不会钻进块里，也不会等你先找父分支。面板底部的提示会写明「在「X」后面插入一步」，确认没有插错地方。多选、拖动过程中不显示这四个箭头，避免挡住整组拖动。

工具栏的「自由布局」是当前模式；点它切到「结构视图」，这时拖节点到别的节点/缝隙才是改顺序（同分支排序、跨分支换层，任意深度互通）。切回自由布局后，手工位置还在。**「整理」**清掉手工位置和手工连线接口，按自动布局重排。手工位置按文件记在这台机器上（`localStorage` 的 `keymouse.layout.v1:<文件路径>`），不写进流程 JSON，所以换机器/把文件发给别人时布局不会跟过去，流程内容不受影响。

**滚轮缩放、左键拖空白框选、右键拖空白平移**，整条主线一直在同一张图上。左下角「适配」把全部节点缩到一屏，适合先看结构；再滚轮放大读细节。长流程的连续鼠标移动/滚轮也不会被折叠成假的一行——每一次都是画布上的真节点，编号仍是文档位置。

没有过滤框和"界面分组头"了：要找一步，先看形状和标题，或者用 `↑` / `↓` 在节点间走；要分段，就用真正的 `if` / 循环块，它们会改变执行路线，而不只是视觉上的抽屉。

## 键盘

| 键 | 做什么 |
| --- | --- |
| `Ctrl+S` / `Ctrl+O` / `Ctrl+N` | 保存 / 打开 / 新建 |
| `Ctrl+Z` / `Ctrl+Shift+Z` / `Ctrl+Y` | 撤销 / 重做 |
| `Ctrl/⌘+点` | 追加或取消一个节点（多选后拖动会整组搬） |
| `Shift+点` | 从主选节点扩展到目标节点 |
| 长按节点 | 把节点加入选择（Windows 图标式多选），再拖整组搬 |
| `Ctrl+A` | 全选画布上的节点 |
| `Ctrl+C` / `Ctrl+V` | 复制当前选中的操作 / 把剪贴板批量粘到主选节点后面 |
| `↑` `↓` | 按画布上的阅读顺序走到上一个 / 下一个节点（父 → 成立时 → 否则） |
| `Alt+↑` / `Alt+↓` | 把当前节点在同一分支里上移 / 下移 |
| `Delete` / `Backspace` | 删掉当前节点（多选时删整组；连同子步骤） |
| `F5` | 播放一遍（跑着时什么都不做） |
| `Ctrl+Enter` | 试运行一遍（只做资格检查，不发送输入） |
| `Ctrl+Shift+A` | 打开「添加」三组操作面板 |
| `Ctrl+Shift+D` | 打包诊断信息（出问题时用，见下面「出问题了」） |
| `Esc` | 依次收起：键盘与版本卡片 → `···` → 添加面板 → 节点抽屉；在跑的时候先停 |

不记得这些键的时候不用翻文档：右上角 `···` 里有这几件：

- **键盘与版本…**：键位表 + 这一份流程用的是哪个命令行、什么版本、哪个环境（开发树还是安装版）；
- **体检（doctor）**：跑一次命令行的环境自检，结果贴进下面的输出面板——报告问题时连同它一起贴；
- **看崩溃日志**：打开 `%LOCALAPPDATA%\KeyMouse\editor-crash.log`（正常情况是空的）；
- **打包诊断信息…**（`Ctrl+Shift+D`）：把环境、体检、崩溃日志尾部、设置账本写进一个文件夹再打开它，见下面「出问题了」；
- **在文件夹里看这个流程**：用资源管理器定位当前文件。

## 出问题了？把诊断打包给作者

`Ctrl+Shift+D`（或 `···` → 打包诊断信息…）会在
`%LOCALAPPDATA%\KeyMouse\diagnostics\<时间戳>\` 下写五份文件，然后打开那个文件夹：

| 文件 | 里面是什么 |
| --- | --- |
| `环境.txt` | 外壳认到的命令行、版本、开发树还是安装版、有没有提权 |
| `体检.txt` | `KeyMouse doctor` 的完整输出 |
| `崩溃日志尾部.txt` | 最近 400 行崩溃记录（没崩过就没有这个文件） |
| `设置.json` | 最近打开的流程、窗口位置与大小 |
| `说明.txt` | 这份清单本身 |

**里面没有截图、没有输入的文字、没有剪贴板**；但会记着流程文件的路径——不想给就先删那几行。
全程本地，不联网、不上传，发不发由你决定。

## 界面：一张无限画布，右侧抽屉

窗口从上到下是四段：顶栏、工具栏、**无限画布**、底部输出。没有左边那条步骤列表，也没有把检查器固定占掉半屏：整份流程铺在画布上，点哪个节点，右边的抽屉才滑出来显示它的参数。

| 位置 | 是什么 |
| --- | --- |
| 顶栏 | 左：`KeyMouse` + `流程编辑器`；中：文件名与路径（未保存时显示「还没有打开流程」+「未保存」）；右：齿轮（设置，`Ctrl+,`）、撤销/重做、新建/打开/保存/另存为 |
| 工具栏 | 左：「＋ 添加」打开三组操作面板；中：`自由布局` / `结构视图` 切换、`整理`、节点总数与画布手势提示；右：`录制`（旁边 ▾ 里还有「以管理员权限录制」）、`试运行`、`播放`；运行时 `播放` 变成 `暂停` + `停止`；最右 `···` 是打开/保存/另存为/从屏幕取区域 |
| 画布 | 全部步骤。自由布局下可任意摆位；结构视图下顶层从上到下、块里的子步骤在右边往下展开。三种轮廓对应三组操作：**流程控制**（六边形）、**循环控制**（胶囊）、**操作指令**（纸卡） |
| 抽屉 | 点节点后从右侧滑出：契约生成的全部字段、证据图、JSON、复制/上移/下移/删除；点空白或 `Esc` 收起 |
| 底部 | 运行输出：消息与日志，运行时会自动展开 |

**画布手势**：滚轮以鼠标为中心缩放；**左键拖空白框选多个节点**，**右键拖空白平移画布**；自由布局下拖动节点只改位置，选中块时连同子步骤整组搬；节点可以拖到左侧/上方的负坐标区，画布不会裁掉它，点「适配」也会把它算进视野。要改流程顺序，先切「结构视图」，再把节点拖到同分支/别的分支的缝隙里，或拖到另一个节点卡片上放到它后面（同一层级），所以二级可以拖到一级、一级也可以拖到三级，任意深度互通。`Ctrl/⌘+点`多选，`Shift+点`范围选择，长按节点加入选择，拖动其中任意一个会整组搬；点节点打开详情。左下角 `− / 百分比 / ＋ / 适配` 控制视野，`适配` 会把整张图缩到一屏。编号就是文档里的位置（`3`、`6.1`、`6.e1`），跑完一步的 ✓/✗ 结果直接落在对应节点上；分组/循环展开多少次都还是同一个编号。

## 设置页：一页文档，不是一弹窗

点顶栏那个齿轮（或 `Ctrl+,`），整个窗口换成**设置页**：报头、章节号 `✦✦✦ 01 ✦✦✦`、术语定义式的行，读起来像一张印好的表。
再点右上角「← 返回流程」或按 `Esc` 回来。

里面有三组真能改的东西：

| 章节 | 能改什么 | 存哪 |
| --- | --- | --- |
| 01 外观 | 三套主题：纸白 / 牛皮纸 / 午夜墨（只换纸与墨，朱砂不换） | `editor-settings.json` 的 `theme` |
| 02 文件 | 最近列表逐条去掉或清空；设置账本在哪个目录 | `recent` |
| 03 环境 | 命令行路径（复制/在文件夹里看）、跑一次 `doctor`、打包诊断 | 不存，现读 |

设置页不自己判断环境：判断只在命令行里有一份，这里只把它的输出原样贴回来。
## 两个编辑器现在差在哪

> 2026-10-31 起，这张表里只剩"权限路线不同"，功能面上没有一栏写"没有"。新外壳是默认入口
> （开始菜单与 `KeyMouse flow edit` 都指向它），老外壳还会随安装包装着，直到确认不再需要。

功能逻辑以老外壳为准，两边**逐项对照**如下；还差的会如实写"没有"：

| 事 | 新外壳 | 老外壳 |
| --- | --- | --- |
| 检查器字段 | 按流程格式契约渲染，点节点后从右侧抽屉展开 | 一样（同一份契约） |
| 取点 / 取一块 | 有：坐标/区域字段后面的「取点」「取一块」，选完连窗口一起填 | 有 |
| 加/删/排序/撤销 | 有（「＋添加」三组面板、节点拖动排序、抽屉底部复制/删除、`Ctrl+Z` / `Ctrl+Shift+Z`） | 有（另带拖拽排序） |
| 试运行 / 播放 / 停止 | 有（同一套命令行，一次跑一条；**没保存也能跑**，跑的是临时副本；播放时主窗口隐藏，左上角日志 HUD；停止按 `Ctrl+Alt+Q`） | 有（多一个暂停/继续） |
| 运行结果写在节点上 | 有：按报告里的 `origin`（`3`、`6.1`、`6.e1`）落到对应节点，分组展开几次都落在同一个节点 | 有：直接写在那一步右边 |
| 控制流块 | 有：`if/while/do/for` 在画布上展开两条/一条分支，`set/assert/break/continue`、条件输入、`probe` 都在抽屉里；`for` 是初值/条件/每轮三格 | 字段按契约渲染，但子步骤与 `else` 要在「这一步的 JSON」里改 |
| 录制 / 播放时窗口 | 默认隐藏主窗口；左上角留一块只读日志 HUD（最近 7 步、鼠标穿透、无按钮）；停止按 `Ctrl+Alt+Q` | 录制缩成细带；播放不隐藏 |
| 最近文件、窗口位置与大小 | 有（空状态列最近 5 条；关窗时记住位置与大小，下次照原样开） | 有 |
| 录制提权窗口 | 有按钮：`录制 ▸` → 「以管理员权限录制」（弹一次 UAC；那一轮界面停不了，得按 Ctrl+Alt+Q 或 0.3 秒内连按两次 Esc） | 有（启动即提权，因此整轮都能停） |

底部「运行输出」是整份界面的消息去处：常规消息、警告、错误都写成以 `# 提示` / `# 注意` / `# 错误` 开头的一行加缩进说明。它自己会展开（占窗口三成高，约 140–260 像素）。**正常使用时它只摆输出本身**：不铺环境、命令行、版本那几行——那些在设置页和诊断包里，摆在面板里只是占地方。出状况才在面板底部冒出一条窄提示（有步骤报错、被提权、或找不到命令行），右侧直接给「打包诊断信息」。
新输出会**跟着滚到底**，所以你看到的是最新几行；往上翻看旧日志时它不会抢你的位置，回到最底下就又跟上了。面板右上角「清空」，日志留最近 900 行或 40 万字符。在输出里拖选文字后点「复制选中」，只会复制你选中的那一段；没有选中时按钮是灰的。

## 加一步

点工具栏左边的「＋ 添加」（或按 `Ctrl+Shift+A`），面板按三类排开：

- **流程控制**：调用另一个流程、条件分支、跳出循环、进入下一轮、设变量、断言；
- **循环控制**：重复 N 次、逐个遍历、条件循环、先做一遍、计数循环；
- **操作指令**：切换窗口、输入文字、等文字出现、找字并点它、点击、拖动、移动鼠标、滚轮、按键、等待时间、等窗口出现、读屏取字。
- **「按键」只有一个字段**：单键写 `enter` / `f5`，组合键用 `+` 写 `ctrl+shift+s`；旧文件里的「单个键名」会在打开时自动并入这个字段。

每项右边写着必填项数量。点一项就加一个节点；面板不会自己关，可以连着加。**选中块节点时新节点进块的第一条分支；选中普通节点时加在它后面；什么都没选就加到顶层末尾。**

新节点是半成品（例如条件分支只缺 `cond`），节点上会标「待补」，右侧抽屉会说还缺什么。块节点的分支在画布上直接展开：`if` 有「成立时 / 否则」，循环只有一条「循环体」；空分支会显示一个虚线槽，点「＋」就能放第一步。

## 改一步：右侧抽屉

点画布上的节点，右边滑出抽屉；点空白处、按 `Esc` 或右上角 `×` 收起。抽屉里的每一格都从契约 `flow.schema.json` 生成：契约里没有的字段，界面上不会凭空多出来。三条读法：

- **默认值**直接显示在输入框里（灰色占位），留空就是不写这个参数；
- 字段名右边的 ⓘ 是这一格的说明；标「必填」的字段没填，抽屉顶部会先给一句「还缺 …」；
- 取值受限的字段是下拉（枚举的第一项「（默认）」= 不写），数字字段带范围。

有些字段可以用鼠标在屏幕上"指"出来：点/区域字段下面有「取一点」「取一块」两颗按钮，和文件菜单里的「从屏幕取区域…」是同一套浮层（见下一节）。

抽屉最下面「JSON」展开后是这个节点在文件里的真实内容（只读），排查"界面以为改了、文件里没改"时看它。底部一排是**＋子步骤 / 复制 / 上移 / 下移 / 删除**；块节点的子步骤也可以直接在画布上增删和拖动排序，不必先开抽屉。

**前提（`when`）**：检视器里有一个开关「满足才执行」——打开后先读一次屏幕，读到指定文字才执行这一步；关掉就等于没有前提，不会留半截字段。「前提要读的窗口与区域（默认就是这一步的）」默认收起，需要盯别的窗口时才展开。

## 从屏幕取点、取区域

- **主窗口会先隐藏**：点「取点」「取一块」或「从屏幕取区域…」时，编辑器自动收起，屏幕只留取点浮层；选完或取消后自动回来。这是默认行为，不需要额外开关。
- **取区域**：浮层上拖出一个框；单击则选整个客户区；`ESC` 取消。
- **取点**：在屏幕上点一下就结束；`ESC` 或右键取消。

选完有两件事同时发生：坐标写进当前字段；如果坐标落在**客户区/窗口**，该窗口的 `process` / `title` 会顺手填进这一步的 `target`；落点是**屏幕坐标**时不绑定窗口，也不自动读进程名。写进文件的区域一律是**目标窗口客户区**相对坐标；取点只有在"这一步没有目标窗口、就发到这个屏幕位置"时才写屏幕坐标。

取消不会改动任何东西——底部只会多一句「取消了，没有改动。」。

## 录制

点「录制」→ 一个确认框（会真开始录，还可能丢弃未保存的改动，所以它必须问）→ 编辑器窗口隐藏，左上角出现一块运行日志 HUD，操作照常做。

停止有三条路：按 **Ctrl+Alt+Q**（录制进程的全局热键）、**0.3 秒内连按两次 `ESC`**，或到设定的时长自动停。
两次 `ESC` 离得太远就不算双击，第一次会当成一次普通按键记进流程（它最多等 0.3 秒确认）。
HUD 没有按钮，也不会抢鼠标；停止后编辑器窗口自己回来，流程读进编辑器。万一 HUD 没起来，用 `Ctrl+Alt+Q` 结束这一轮。

要点：

- 录到的流程先落在临时目录的 `keymouse-record.json`（默认 `%TEMP%`，不可写时退到备用目录，见 `KeyMouse doctor`），读进编辑器后算「未命名」——想留住它得自己 `Ctrl+S` 或另存为；
- 录制期间窗口是藏起来的，看不见按钮是正常的，用热键结束；
- 一步都没录到时会明说没有产生流程文件，而不是给你一个空文档。

**新外壳（`KeyMouse.Editor.exe`）里的录制**：点「录制」先弹一次「把这次录制存到哪」（存不下来就没法录），
然后编辑器主窗口**默认隐藏**，屏幕左上角出现日志 HUD：
标题「运行日志」，下面最多 7 行，每行是 `[x/y] 步骤名 : 精简内容 状态`；当前步骤的 `执行中` 行用朱砂左边框标出。
HUD 透明、置顶、**鼠标穿透**，不抢焦点，也没有停止按钮——它只是让你知道脚本现在走到哪一步。
它还会被标记为**不参与屏幕抓取**：识别文字、找字、截图看到的是 HUD 底下的窗口，不会把日志文字当成目标内容（Windows 10 2004 及以上）。

停止动作本身不会被录进流程（录制参数里排掉 `KeyMouse.Editor` 自己）。
停下后 HUD 自己消失，并把录到的那份打开。两边录出来的文件格式完全一样。

> HUD 为什么是**第二块**窗口而不是把主窗口缩成一条：
> 录制/播放时脚本会接管鼠标，主窗口上的按钮点不到；HUD 只读，就不需要用户去点它。
> 透明窗口与 `WS_EX_TOOLWINDOW` 的取舍写在 `src-tauri/src/overlay_style.rs` 的文件头里。

**要录管理员窗口上的操作**：点「录制」右边那个 `▾`，选「以管理员权限录制（会弹 UAC）」。
Windows 只允许同级或更高权限的钩子看见输入，所以不这么做的话，提权窗口上的点击一个也录不到。
代价得先说清楚：

- 这一轮会**弹一次 UAC**，点「是」才开始录；点「否」就什么也没发生（界面会说"UAC 被拒绝了"）。
- 这一轮**只能你自己停**：按 `Ctrl+Alt+Q`，或连按两次 `Esc`。界面这边既送不进键、也杀不掉那个
  提权进程（Windows 的 UIPI 拦着），所以工具栏上不会摆一个按了没用的「停止」。
- 这一轮**不隐藏主窗口**：提权进程停不下来时，主窗口上的说明是唯一能读到的"怎么停"；藏起来反而更糟。
- 录完照样自动打开那份流程。

## 看证据：录制时那一步长什么样

录制时引擎会把每一步"当时看到的窗口画面"存成 PNG，落在流程文件旁边的 `<流程名>.shots\` 里
（`0001-click.png` 这样命名，一次录制一组，重录覆盖同一组）。

选中那一步，右侧抽屉最下方就是「证据」：缩略图 + 文件名 + 「看大图」「在文件夹里看」。
画布节点右上角有个 ▣ 记号，先扫一眼就知道哪些步骤有图。

两点要知道：

- **回放不会重拍**。图永远是你录这一遍时的样子；窗口改了大小、界面换了样之后，图和现实可能对不上——
  它证明的是"当时"，不是"现在"。
- 图不在流程旁边时（被删了、流程被搬走了）抽屉会如实说读不到，不会拿一张别的图凑数。

## 试运行与播放

两个按钮的差别只有一条：

- **试运行**：只做资格检查（窗口在不在、最小化没有、区域能不能用），**不发送任何输入**，也不存截图；
- **播放**（F5）：真的发。

跑之前编辑器先保证"跑的就是你看到的"：文件已经存过、也没有未保存改动，就直接跑那个文件；否则把你的当前内容写进临时目录的 `%LOCALAPPDATA%\KeyMouse\tmp\editor-run.json` 再跑——未保存的改动照样生效，又不会覆盖你正在编辑的正式文件。

**播放默认先隐藏编辑器主窗口**：左上角出现日志 HUD（最近 7 步、当前步骤高亮），目标窗口不再被编辑器挡住。按 `Ctrl+Alt+Q` 停止；结束后 HUD 关闭、编辑器自己回来。试运行不隐藏（它只查资格，不发输入）。

跑完底部会出现一条结论：`N 步全部成功…退出码 0：整条流程都成功了。`，或者「第 K 步「某动作」失败。前面几步成功。」；节点上也会标 ✓/✗。退出码含义与命令行完全一致：

| 退出码 | 意思 | 能不能直接重跑 |
| --- | --- | --- |
| 0 | 成功 | — |
| 1 | 运行时失败（例如 `SendInput` 被 UIPI 拦截） | 先解决权限/被拦的原因 |
| 2 | 参数错误、流程本身不合法 | 改流程 |
| 3 | 没等到、没匹配上，或选区被取消 | 可以（没发任何输入） |
| 4 | 目标窗口不可用（最小化、被遮盖、无响应） | 可以（没发任何输入） |
| 5 | 焦点没验证通过 | 可以（没发任何输入） |
| 6 | 没读到内容（区域不对、引擎看不懂） | 可以（没发任何输入） |
| 7 | 被取消 | 可以（取消点之后没发输入） |

## 保存、另存

`Ctrl+S` 保存，`Ctrl+Shift+S` 另存为，`Ctrl+O` 打开；都在「文件」菜单里。标题栏右侧的 `●` 一出现就表示有未保存改动。

保存前会先校验必填项：缺东西时底部会说「第 N 步有 M 处必填项没填，已在对应字段下方标出。」——先在抽屉里把这些格子填了。直接点「试运行」/「播放」不会先拦你：引擎会以退出码 2（流程不合法）或某一步失败的形式告诉你哪里不对。

## 什么会打断你

只有**会丢东西**的动作才弹对话框（`ContentDialog`），其余反馈一律走底部那条消息带，不遮画面：

| 时机 | 对话框 |
| --- | --- |
| 关闭窗口、新建、打开别的文件，而当前流程有未保存改动 | 「有未保存的改动 / 关掉之前要保存吗？」或「…前先保存吗？」，按钮 保存 / 不保存 / 取消 |
| 开始录制 | 「开始录制」，说明停止方式，按钮 继续录制 / 取消 |

「添加」的步骤选择面板是浮层（点外面关闭），不是对话框。

## 崩溃了去哪看

编辑器把三类未处理异常都写进同一个文件：`%LOCALAPPDATA%\KeyMouse\editor-crash.log`，一行时间戳加一行异常，作用域写着「UI 线程」「非 UI 线程」或「未观察的 Task」。UI 线程的异常被记下后**程序继续跑**（不弹窗、不退），所以"刚才那下没反应"先翻这个文件。

## 控制流步骤（if / while / do / for / set / assert / return）

C 风格的 `if/else`、`while`、`do-while`、`for`、`break/continue`、`return`、`set`、`assert` 在**新外壳（Tauri）**里是完整的块行。
想直接看长什么样：打开仓库里的 `samples/control-demo.json`，里面一条 `while` 带 `if/else` 和 `break`，一条 `for` 带三段式，还有一条按 `text("保存")` 分支的 `if`。

**箭头按执行路线画，不按节点上下位置画**：`if` 从节点边缘分出「成立」「否则」两条线，各自进对应分支；分支走完汇到 if 后面的下一步。循环体末尾同时有「返回」回循环开头和「退出」去下一步；`break` 只画「跳出」到循环后面，`continue` 只画「继续」回循环开头；`return` 结束当前流程，没有后续箭头。把这些节点拖到任意位置，线的起终点会跟着节点边缘和夹角重新选边，方向不会反；也可以点选连线后拖两端圆点手工指定接口。自由布局里也仍可点节点改参数、加子步骤；要改执行顺序，切「结构视图」拖到缝隙。

- **新建**：`Ctrl+Shift+A`（或「＋添加」）→「流程控制 / 循环控制」组：条件分支、条件循环、先做一遍、计数循环、跳出循环、进入下一轮、结束流程、设变量、断言。
- **`return` 只结束当前流程**：放在被 `call` 的子流程里，会按 `export` 交回变量并让调用者继续；放在根流程里就是正常结束整次运行。它能在 `if`/循环里用，但**不越过 `call` 边界**；同一流程里它后面的步骤不会执行。
- **块的子步骤就在节点右边**：沿画布往下读；`if` 有「成立时」与「否则」两条分支，分别可加/删/排序。编号写成 `6.1` / `6.e1`，和命令行报告的 `origin` 是同一套——否则分支的 `.e` 就是 engine 的写法。
- **条件直接从选项里挑**：抽屉的「条件类型」有总是成立/从不成立、比较两个值、屏幕上读到文字、窗口存在、窗口在前台、上次读到的文字、运行超过 N 毫秒；选完只填带「必填」的项，下方会实时显示生成的条件。选项覆盖不了的旧写法可切到「自定义表达式」。
- **用 `text()` 时下面会展开「条件读哪里」**（窗口 + 区域 + 匹配方式 + 容错），目标与区域都是必填；没填完时节点会标「待补」，播放前也会拦。`found()` 不需要观察点。
- **`for` 是三个小格**：初值 / 条件 / 每轮之后。初值和每轮之后都是「名字 = 表达式」的小表，可增删；`continue` 之后 `step` 照样执行，和 C 一样。
- **`set` 的值、`assert` 的条件**同理：`set` 的值仍是表达式，`assert` 的条件也走选项；`maxRounds` 在抽屉里可直接改（默认 200 / `for` 10000）。
- **块不能挂 `when`**：契约里标了 `noWhen`，抽屉不会画那个开关；条件写进 `cond`。`break`/`continue`/`return` 同样不能挂 `when`。
- **引擎仍会拦**：`break`/`continue` 不在循环里、条件表达式拼错、`text()` 没给观察点——这些在保存后由命令行加载时给出具体位置；编辑器只负责不把明显的缺项做丢。

老外壳（WinUI）按契约渲染这些步骤的字段与中文名，但 `if` / 循环的子步骤仍要在「这一步的 JSON」里编辑；新外壳可以把它们当普通行一样加删、选中、改字段。

## 开发版与发布版

标题栏写着身份，一眼能分清手上这份是什么：

```
KeyMouse 流程编辑器 2.2.4（构建 10-26 21:33 · 管理员）
```

- **构建时间**是这个 exe 的写入时间，用来区分"刚编的"和"上周装的"；
- **管理员 / 普通权限**是启动时的身份。**老外壳**带 `requireAdministrator`，启动即提权——不提权就录不到、也点不动以管理员身份运行的程序；开发构建走的是同一份清单，所以开发时也是「管理员」。**新外壳相反**：界面进程始终是普通权限，需要权限的动作交给 `KeyMouse.exe`（录制用当前权限，因此录不到管理员窗口上的操作，命令行会把这句话写进输出）；
- 只是调界面、不想每次弹 UAC（或者想让普通权限的 `KeyMouse` 去点它），用 `pwsh tools\dev\km.ps1 e -NoElevate` 编一份普通权限的，标题会显示「普通权限」；
- 提权的副作用：系统文件选择器在提权进程里会失败，编辑器改用经典对话框，用起来没差别；
- 两种形态都通过 `ProductLayout` 统一找命令行，所以开发树里**没有** `cli\` 文件夹是正常的——完整顺序见[开发树与安装版](environments.md)。

用普通权限的开发版验证界面改动、用发布版验证"真能录到管理员窗口"，是仓库里一直沿用的分工；怎么编译与打包见[开发与发布流程](../dev/development.md)。
