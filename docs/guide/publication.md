# 哪些内容可以公开

先判断文件为什么存在，再判断内容能不能公开。扩展名不是标准：手写的 JSON 示例与录下的键盘输入格式相同；应用图标是构建输入，而桌面 PNG 可能含私人信息。

| 保留在仓库 | 留在本机或 CI 受控存储 |
| --- | --- |
| 源码、schema、工作流、依赖锁文件、打包用项目图标 | `bin/`、`obj/`、`target/`、`node_modules/`、`artifacts/`、安装器载荷 ZIP |
| 手工编写的 `samples/`、用虚构目标生成的协议夹具、共享构建/调试任务 | 真实录制 JSON、`.shots/`、OCR 图片、运行报告、日志、崩溃转储、本机 IDE 偏好 |
| 相对仓库路径、环境变量名、故障的最小复现 | 用户目录、主机与窗口清单、剪贴板、账号、访问令牌、签名证书私钥和密码 |

**录制前**：在空白靶窗操作，使用虚构文本；需要保存的本地流程放 `local-recordings/` 或仓库外。`--no-shots` 只关闭截图，不会清除已输入的文本。反馈问题时优先重新构造一个最小流程，而不是试图遮盖整份真实录制。

**提交前**：从仓库根目录运行下列只读检查。第一条扫描当前跟踪文件与未忽略的候选文件；第二条直接检查 Git 索引中的版本，能发现「工作树已脱敏、暂存区仍是旧内容」的情况。

```powershell
python tools/dev/check-public-files.py
python tools/dev/check-public-files.py --index
git status --short
git diff --cached --stat
git ls-files -ci --exclude-standard
```

[检查器](../../tools/dev/check-public-files.py)只报告命中类别和文件名，不打印秘密。无命中**不是**隐私保证：自定义格式的凭据、业务数据、二进制内容、历史提交与已有 Release 附件仍需人工复核。不要因规则报错就全局放行文件类型；测试用的虚构数据应有来源和用途。

**如果已经提交**：`.gitignore` 对已跟踪文件不生效。用 `git rm --cached -- <文件>` 可保留本地副本、停止日后跟踪，但不会擦除旧提交。若泄露的是凭据应先撤销或轮换；是否清理历史、发布附件、协作者副本和缓存，须由维护者另行确认。不要为清理文档自动强推。
