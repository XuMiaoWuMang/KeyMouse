# 按失败现象排查

先记下失败的**步骤编号、退出码、坐标空间和操作类型**。`--dry-run` 是不发送输入的检查，不是一次成功播放。不要为了诊断把整段键盘录制贴到公开 Issue。

| 现象 | 检查顺序 |
| --- | --- |
| 编辑器没启动，或更新后字段没变化 | 检查 WebView2；从终端运行同一目录的 CLI `--version`、`schema`。核对[环境](environments.md)，避免安装版界面读取旧开发 CLI |
| `exit 3`：目标不存在、不唯一或等待超时 | 用 `window list --json` 确认候选；客户区步骤核对进程、窗口类和已填写的标题；OCR 步骤核对区域、匹配条件和超时 |
| `exit 4`：后台动作被拒绝 | 核对录制/回放进程与目标的用户、会话、完整性和 UIAccess 状态。管理员与普通窗口不是同一权限上下文；不要通过给整个编辑器提权来试错 |
| `exit 5` 或键入了错误窗口 | 检查当前前台窗口、焦点策略及键盘步骤是否需要显式 `focus`。`--focus-policy never` 不会把普通键盘输入变成后台输入 |
| 点偏或没有效果 | 区分屏幕坐标与客户区坐标。窗口移动、缩放或内容重排后重新取点。最小化并不保证目标仍处理坐标消息；标准编辑框/按钮可另外用 `background` 验证 |
| `exit 6`：读不到文字 | 先看区域是否包含整行，再核对截图方式和 OCR 模型。截图是否为空与识别是否准确是两件事 |
| 每步似乎多停一秒 | 检查 `delayMs` 是否缺省、是否另加手动 `sleep` 或全局 `--delay`。只需要立即执行时填 `0` |

需要反馈时，在空白测试窗口用虚构文本复现，附版本、最小流程和经过检查的错误行。若要提供图像，截取靶窗而不是整张桌面。见[公开材料检查](publication.md)。
