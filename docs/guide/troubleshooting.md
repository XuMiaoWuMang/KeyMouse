# 故障排查

按症状查。每条都是三段：**症状**（你看到什么）、**为什么**、**怎么办**。
动手之前先跑一次 `KeyMouse doctor`——它一次说清环境判定、版本、权限、编码、注册表，以及命令行与编辑器各自是在哪儿找到的：

```pwsh
KeyMouse doctor
```

```
环境：安装版
仓库：无（安装版没有源码树，这是正常的）
自己：C:\Users\你\AppData\Local\Programs\KeyMouse\cli

命令行：C:\Users\你\AppData\Local\Programs\KeyMouse\cli\KeyMouse.exe
        来自：自己所在目录
编辑器：C:\Users\你\AppData\Local\Programs\KeyMouse\KeyMouse.FlowEditor.exe
        来自：自己所在目录（安装版：编辑器与命令行同在 <安装目录>\ 时）

版本：0.2.1（引擎 2.1.0）
权限：普通用户（提权窗口会拦下输入）
编码：输出用 utf-8（跟随控制台码页；重定向时按 UTF-8）
注册表：HKCU\Software\KeyMouse GuiPath=C:\…\KeyMouse.FlowEditor.exe CliPath=C:\…\cli\KeyMouse.exe

检查：
  ok   命令行可用
  ok   编辑器可用
  ok   流程 schema 打得开
```

（你机器上的路径与编码当然不一样，`ok` 那三行才是要看的。）

| 症状 | 去哪一节 |
| --- | --- |
| 编辑器说「连不上 Runner」 | [编辑器找不到命令行](#编辑器找不到命令行) |
| 编辑器双击没反应 / `XamlParseException` | [编辑器起不来](#编辑器起不来xamlparseexception--缺-pri) |
| 中文变成「宸茬Щ鍔ㄥ埌」 | [命令行输出乱码](#命令行输出乱码) |
| 退出码 3 | [没找到窗口、多候选、超时](#退出码-3没找到窗口--多候选--超时--选区取消) |
| 退出码 4 | [目标窗口不可用](#退出码-4目标窗口不可用) |
| 退出码 5 | [焦点没验证通过](#退出码-5焦点没验证通过) |
| 退出码 6 | [没读到内容](#退出码-6没读到内容) |
| 提权窗口点不动 / 上报 1223 | [提权窗口被拦下](#提权窗口被拦下uipi) |
| 编辑器改的引擎代码不生效、报「不认识 --parent」 | [安装版与开发版混用](#安装版与开发版混用) |
| 点在别的位置、区域读错行 | [坐标不对](#坐标不对客户区-vs-屏幕) |

退出码的完整定义在[命令参考](../reference/cli.md#退出码)；`3 / 4 / 5 / 6` 都属于**没有发出任何输入**，改完可以放心重跑。

## 编辑器找不到命令行

**症状**：编辑器能开，但一点「试运行」「播放」「录制」或者取区域，底部就出现「连不上 Runner」。消息是这几种之一：

```
找不到 KeyMouse.exe。开发树里它由 tools\build\build.ps1（或 km d）产出到 artifacts\cli\。
找不到 KeyMouse.exe。安装版里它应当在 <安装目录>\cli\ 下，重装一次可以修好。
启动 serve 之后没能连上命名管道。
```

前两句后面还会跟一句「各候选路径与选中结果：命令行跑一次 KeyMouse doctor。」，连不上管道时再加「它说：<原因>」。

**为什么**：编辑器自己不回放、不录制、不读屏——这些都交给常驻的 Runner，而 Runner 就是命令行 `KeyMouse.exe serve`。找不到命令行，编辑器就只是一个编辑器。命令行不在"编辑器旁边"，也不在注册表登记的地方，就找不到。

**怎么办**：

1. 用 `KeyMouse doctor` 看「命令行：」那行指向哪里、后面「来自：」写的是哪条约定；找不到时它会把你检查过的每个位置都列出来。
2. 装过安装版的，确认 `<安装目录>\cli\KeyMouse.exe` 真的在。装的时候取消过「一起装命令行」的话，它就不在——重跑安装程序，勾上更新命令行。
3. 想让编辑器用某一份特定的命令行，就设环境变量再启动它：

   ```pwsh
   $env:KEYMOUSE_CLI = 'D:\Tools\KeyMouse\KeyMouse.exe'
   ```

4. 开发树里先跑一次 `pwsh tools\build\build.ps1`（或者 `.\km e`），它会产出 `artifacts\cli\KeyMouse.exe`——开发树的编辑器读的就是这一份。
5. 消息是「命名管道拒绝访问」那种，说明**已有一个更高权限的 Runner 在跑**，转到下一节的"权限对齐"。

查找顺序的完整说明在[开发树与安装版](environments.md)。

## 新外壳启动时黑框一闪 / 窗口总在最前

两个都是外壳自己的事，已经修掉；看到其一说明你手上是旧版本（重装或重新 `.\km ub`）。

- **黑框一闪**：两层原因。① 外壳自己曾经是控制台程序（Rust 默认），启动就带一个黑框，
  现在用 `windows_subsystem = "windows"` 关掉了；② 命令行 `KeyMouse.exe` 也是控制台程序，
  外壳每次打开文件、取点、跑流程、读契约都会起它一次，现在统一带 `CREATE_NO_WINDOW`
  （见 `src-tauri/src/process.rs`），命令行照跑，只是不显示窗口。
- **窗口总在最前**：只有"录制时的细带"会临时置顶，停止录制会还回去。如果退出时没还成功
  （比如被强杀），下次启动的外壳会显式把置顶清掉。

真遇到了先确认版本：`.\km ub` 重新打包，或看安装目录里的 exe 时间。
## 编辑器起不来：缺 WebView2 运行时（新外壳）

**症状**：双击 `<安装目录>\KeyMouse.Editor.exe`，进程起来一瞬间就退了，没有窗口、没有报错框。

**为什么**：新外壳（Tauri）不自带浏览器内核，界面靠系统的 **Microsoft Edge WebView2 运行时**。Windows 11 与更新过的 Windows 10 都自带；精简系统、长期没联网更新的机器可能没有。

**怎么办**：

1. 看安装目录里有没有 `先读我-需要-WebView2.txt`——安装程序发现缺运行时会放这份说明（它**不会**让安装失败，命令行也不受影响）。
2. 装一次运行时，免费、在线安装包约 2 MB：[developer.microsoft.com/microsoft-edge/webview2](https://developer.microsoft.com/microsoft-edge/webview2/)。
3. 不想装运行时也行：同一目录里的 `KeyMouse.FlowEditor.exe`（老外壳，自包含）功能一样全。
4. 确认到底有没有：注册表 `HKEY_LOCAL_MACHINE\SOFTWARE\WOW6432Node\Microsoft\EdgeUpdate\Clients\{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}` 的 `pv` 值就是版本号；安装程序的日志里也会写一行 `webview2 <版本>`。

## 编辑器起不来：XamlParseException / 缺 .pri

**症状**：双击编辑器没有窗口，或者窗口一闪就没了；错误信息里有 `XamlParseException`。手动从命令行启动会看到异常文本：

```pwsh
& '<安装目录>\KeyMouse.FlowEditor.exe'
```

**为什么**：发布目录里少了 `KeyMouse.FlowEditor.pri`。`dotnet publish` 不会自动带上 WinUI 的这份 XAML 资源，缺了它界面在解析阶段就失败——不是你的操作问题。另一个同源原因是语言目录被搬走了：WinUI 的 MRT **只认 exe 旁边的文化目录**，把 `en-US` 之类的目录收进 `language\` 之类的子目录同样会崩。

**怎么办**：

1. 确认 `<安装目录>\KeyMouse.FlowEditor.pri` 存在。缺了就是安装包/发布目录不完整——重装，别从别处单独拷一个 exe 过来。
2. 整个目录一起拷贝：编辑器是"一堆文件 + 一个 exe"，只拷 exe 必然起不来。
3. 不要手工移动或改名 exe 旁边的语言目录（`en-US`、`zh-CN` 等）。
4. 翻一下 `%LOCALAPPDATA%\KeyMouse\editor-crash.log`，里面会有带时间戳的异常行。
5. 装的过程有问题时看 `%TEMP%\keymouse-setup.log`（`%TEMP%` 不可写时看 `KeyMouse doctor` 报的临时目录）。

## 命令行输出乱码

**症状**：中文显示成「宸茬Щ鍔ㄥ埌」这类乱码，英文数字正常。

**为什么**：KeyMouse 按**控制台自己的码页**输出（cp936 就写 GBK，65001 就写 UTF-8），因为 PowerShell 正是用 `[Console]::OutputEncoding`（跟随控制台码页）去解码原生命令输出的。宿主的码页与解码器不一致，就成了乱码。重定向到文件或管道时程序改写 UTF-8，所以重定向之后又可能反过来乱。

**怎么办**：把两边对齐，两种方向任选一种。全程 UTF-8：

```pwsh
chcp 65001
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
KeyMouse doctor            # 这行会打印「编码：输出用 utf-8」
```

留在中文码页：

```pwsh
chcp 936
[Console]::OutputEncoding = [System.Text.Encoding]::GetEncoding(936)
KeyMouse doctor            # 「编码：输出用 gb2312」
```

重定向到文件再读的时候按 UTF-8 解码：`Get-Content .\out.txt -Encoding utf8`。

## 退出码 3：没找到窗口 / 多候选 / 超时 / 选区取消

**症状**：命令返回 `3`，消息是下面三种之一：

```
没有窗口匹配 --process notepad --title "记事本"

当前可见的窗口：
  0x00120394  notepad(4321)  "新建文本文档 - 记事本"  类名=Notepad  [可见, 响应=3ms]

有 2 个可用窗口匹配——请用 --pick <n> 指定一个：
  [1] 0x...
  [2] 0x...
```

第三种是 `waitfor` / `wait-text` / `wait-window` 等到超时；或者选区浮层被 `ESC` 取消了——`region pick` 会说 `已取消选区——没有产生任何坐标`，`probe --pick-region` 会说 `已取消选区——未读取任何内容`。

**为什么**：选择器没匹配到任何窗口，或者匹配到多个而你没说是哪个。窗口标题会变（文件名、未保存的星号），所以拿整句标题去匹配经常在别人机器上失效。

**怎么办**：

1. `KeyMouse window list` 看现在到底有哪些窗口、标题和状态；窗口藏在托盘里加 `--all`。
2. 选择器放宽一点：用 `--process` 加标题**子串**（`--title 记事本`），少用整句。
3. 有多个候选时二选一：`--pick 1`（1-based，Z 序从上到下），或者把选择器写得更紧。
4. 先看清楚再发输入：`KeyMouse window inspect --process notepad` 会逐个列候选，写清「判定：可用/不可用」和「问题：…」。
5. 等窗口的时间太短：`waitfor <选择器> --timeout 毫秒`，超时本身也是退出码 3。
6. 在流程文件里，同一步骤的等待超时由该步骤的 `timeoutMs` 决定。

## 退出码 4：目标窗口不可用

**症状**：命令返回 `4`，消息形如「目标窗口不可用」+ 每个候选后面的 `-> <原因>`，或者 `「<标题>」在聚焦与注入之间消失了——未发送任何输入`。

**为什么**：窗口找到了，但**现在不能往里发输入**。具体原因就那么几种（`window inspect` 会原样打出来）：

| 原因（原文） | 意思 | 怎么办 |
| --- | --- | --- |
| `窗口已最小化——加 --allow-restore 允许 KeyMouse 还原它` | 最小化的窗口没有可点的像素 | 加 `--allow-restore`；流程文件里写 `"allowRestore": true` |
| `窗口是隐藏的（托盘/后台窗口）——KeyMouse 拒绝隐藏窗口，请先让它显示出来` | 窗口不可见 | 先把窗口显示出来（点托盘图标） |
| `窗口被 DWM 遮盖（挂起的 UWP 应用，或位于其他虚拟桌面）` | 它在别的虚拟桌面，或 UWP 被挂起 | 切到那个虚拟桌面；把应用唤醒 |
| `窗口已被禁用（WS_DISABLED）——它设计上就忽略输入，通常意味着有模态对话框占着它` | 前面压着一个对话框 | 先处理掉那个对话框 |
| `窗口在 500ms 内没有应答 WM_NULL（无响应）` | 主线程卡死 | 等它缓过来，或加 `--retry 2` 再试 |
| `--strict-point` 的报错：`strict-point：x,y 下方的窗口不是目标` | 你那个点上盖着别的窗口 | 换个点，或去掉这个严格检查 |

**怎么办**：先用 `KeyMouse window inspect --process <名字>` 看「问题：」那一行；确认窗口在场后加 `--allow-restore` 或先手动切到那个窗口。`4` 没有发出任何输入，可以直接重跑。

## 退出码 5：焦点没验证通过

**症状**：返回 `5`，消息是 `无法聚焦「<标题>」：尝试 3 次仍未成为前台窗口（当前前台是「<别的窗口>」）；若目标以管理员身份运行，请同样以管理员身份运行 KeyMouse（UIPI 会挡住前台切换与输入注入）`，或者 `focus-policy none：「<标题>」不是前台窗口——未发送任何输入`。

**为什么**：只有你要求"温和聚焦"（`--focus-policy gentle`）或"必须已经是前台"（`--focus-policy none`）时才会出现。前台切换被系统拒绝，最常见的原因是**两边权限不同**——Windows 不允许低权限进程把前台抢到高权限窗口上。

**怎么办**：

1. 默认的 `--focus-policy never` 根本不碰焦点（只换算坐标、校验资格），大多数情况不需要改它；
2. 需要切前台就用 `--focus-attempts 5` 多试几次；
3. 目标是管理员程序时，把 KeyMouse 也提权：`KeyMouse --elevate <原来的命令>`；
4. 用 `--focus-policy none` 时，先自己手动把窗口点到前台。

## 退出码 6：没读到内容

**症状**：`probe`、`read-text`、`wait-text`、`click-text` 返回 `6`，消息有三种：

```
2 次读取结果不一致，判定为没看清（未做出任何判断）：
  第 1 次：…
  第 2 次：…
读到了文字，但置信度 12.4 低于下限 30（实测这个区间基本是乱码）：…
启动 OCR 引擎 'tesseract' 失败——未读取到任何内容
```

**为什么**：读屏走 OCR，三件事最容易坏：区域没框住整行文字、图太糊/对比度太低、引擎或模型没就位。

**怎么办**：

1. 先把那块区域存下来看：`KeyMouse probe --region 0,0,400,32 --keep-image shot.bmp`，用眼睛核对框得对不对（高度一定要盖住**整行**：`0,0,400,20` 会读成乱码，`0,0,400,32` 就正常）。
2. 坐标是**客户区相对**的，不含标题栏；要连标题栏一起读时加 `--space window`。
3. 暗底浅字读不出来：加 `--normalize`；字太小：加 `--scale 2`。
4. 想要更稳就多读几次，逐字一致才算数：`--reads 3`（默认 2）。
5. 引擎没装好会直接说「启动 OCR 引擎 'tesseract' 失败」——装 Tesseract，或者用 `--engine` 指到它的 exe。模型目录默认 `%LOCALAPPDATA%\KeyMouse\tessdata`，不对就 `--tessdata-dir` 指过去；语言默认 `eng+chi_sim`。
6. 读到的文字到底是哪几个词：`--json` 会把逐词置信度一起打出来（命令行参考里还有"找字"的用法）。

## 退出码 1：`Access to the path ... is denied`（临时目录写不进去）

**症状**：`probe`、录制、`wait-text` 这类要用 OCR 的命令直接失败，消息里带一个 `…\keymouse-probe-<pid>.bmp` 的路径，后面是 `is denied`。

**为什么**：OCR 要把截到的像素写成一张临时位图再交给引擎。临时目录首选 `%TEMP%`，但它不一定可写——受限的自动化沙箱、被重定向的配置、被安全策略锁死的用户配置都会这样。这不是流程或坐标的问题。

**怎么办**：

1. `KeyMouse doctor` 看「临时文件：」那一行，它会写出**实际用的**目录，并在退到备用目录时说明原因；
2. 顺序是 `%TEMP%` → `%LOCALAPPDATA%\KeyMouse\tmp` → 程序所在目录。三个都写不进去时会退到程序目录，此时任何写临时文件的命令都会失败——把 `TEMP`/`TMP` 环境变量指到一个可写目录即可（自动化里常用：指到本次运行的目录）；
3. 只想知道屏幕上那块长什么样、不想走 OCR：`probe --keep-image out.bmp` 只截图。

## 打了字却没出现：中文输入法，或这个会话收不到注入

**症状**：`KeyMouse key type "abc"` 报「已输入 N 个字符」，窗口里却一个字都没有；`key press` / `mouse click` 同样"成功但没反应"。桌面冒烟（`tests\smoke\run.ps1`）会因此一口气红几十项。

分两种，表现一样但原因完全不同：

1. **中文输入法在位。** 注入的字符先进候选窗，没提交就落不进文档。按两次 `Shift` 切到英文输入再打即可；冒烟之前也先按两次 Shift。
2. **这个会话收不到注入的输入。** `SendInput` 会**报告成功、事件却被丢掉**——嵌套/沙箱会话、远程桌面窗口被挂在后台、桌面已锁屏时都会这样。

**怎么区分**：跑

```pwsh
pwsh tools\dev\check-input.ps1
```

它往冒烟靶子里打一串固定字、再 `Ctrl+A`/`Ctrl+C` 读回剪贴板：读到那串字就是注入可用（若提示"需要先把输入法切到英文"，按两次 Shift）；两次都读不到就是这个会话收不到输入——换一个真正交互的终端（本机直接开的 Windows Terminal）再来，仍旧失败才是产品问题。

**怎么办**：

- 用中文输入法时：先连按两次 `Shift` 切英文，或者干脆用 `key combo` 发组合键（组合键不走候选窗）；
- 在会话里跑自动化：先跑一次 `check-input.ps1` 确认前提，别对着几十条假红找 bug；
- `verify.ps1` 已经内置这件事：自检返回 3 就把冒烟记为「已跳过」并写明原因，不算失败也不会假装通过。

## 提权窗口被拦下（UIPI）

**症状**：对以管理员身份运行的程序（任务管理器、装好的某些工具）发输入，什么都没发生；或者流程在退出码 `1` 上失败（`SendInput` 被 UIPI 拦截）。用 `--elevate` 时如果 UAC 里点了"否"，退出码是 **1223**，而且**什么都没做**。

**为什么**：Windows 的 UIPI 不允许低完整性进程向高完整性窗口注入输入，也不允许挂全局钩子去录它。这不是 KeyMouse 的限制——任何输入工具都一样。

**怎么办**：

- 单条命令：`KeyMouse --elevate mouse click ...`——它会以管理员身份重跑**同一条命令**（弹一次 UAC），退出码原样带回；
- 整个终端都提权：从管理员身份的 PowerShell 里跑，之后就不用每条都加；
- 编辑器不用加这个参数：安装包装出来的编辑器本身带 `requireAdministrator`，启动即提权，所以它能录、能点管理员窗口；
- 录制时也一样：要录管理员窗口上的操作，录制进程本身必须提权。

## 安装版与开发版混用

**症状**：在仓库里改了引擎代码、重新编译，编辑器里跑起来还是老行为；或者编辑器播放时报「不认识 --parent」这类**只有旧版才有的错**。也可能反过来：`--version` 显示 0.2.1，行为却是别的版本。

**为什么**：编辑器不自己执行，它找一份 `KeyMouse.exe` 来当引擎。查找顺序是"离自己最近的在前、注册表和 PATH 在最后"：开发树里先看 `artifacts\cli\KeyMouse.exe`，安装版才看 `<安装目录>\cli\`。这几种错配都会发生：`dotnet build` 只更新了 `bin\`，没更新 `artifacts\cli`；或者编辑器（开发版）拉起了注册表里上一次装的那个旧命令行。

**怎么办**：

1. `KeyMouse doctor` 看「命令行：」和「来自：」——先确认引擎到底是哪一份；
2. 开发树里改了引擎：跑 `pwsh tools\build\build.ps1`（或 `.\km e`，它会把命令行重新打到 `artifacts\cli`）；
3. 两边版本必须对得上：`KeyMouse --version` 报的版本要和编辑器标题里的版本一致；
4. 想固定用某一份：设 `KEYMOUSE_CLI` 指向它，再启动编辑器；
5. 装了两个版本的安装包：`doctor` 里「环境：安装版」那一段会写清自己在哪个目录，注册表那行写清登记的是哪一份。

## 坐标不对：客户区 vs 屏幕

**症状**：点在想要的元素旁边几十像素；区域读到的不是那一行；同一个坐标在不同机器上落在不同地方；窗口最大化后全偏。

**为什么**：KeyMouse 有两套坐标系，写混了就会偏：

- `-x X -y Y`：**绝对屏幕像素**（左上角是屏幕原点）；
- `-wx X -wy Y`：**客户区相对**（左上角是窗口内容区，不含标题栏与边框）；
- `probe --region`：默认也是客户区相对（`--space client`），`--space window` 才相对整个窗口。

窗口一移动、一缩放，客户区坐标不变，屏幕坐标就变了——这正是为什么流程文件里记的是客户区坐标。

**怎么办**：

1. 先确认这一条命令吃的是哪种坐标：点窗口内容一律用 `-wx/-wy`（必须**成对**出现，并且带窗口选择器）；
2. 用 `KeyMouse region pick` 直接取，不靠估算：

   ```pwsh
   KeyMouse region pick                 # 拖框取区域，打印可用的命令
   KeyMouse region pick --point         # 单击取一个点
   ```

3. 编辑器里取点/取区域写进文件的永远是**目标窗口客户区**坐标（只有"没有目标窗口"的步骤才写屏幕坐标）；取完检查一下这一步的 `target` 有没有填上窗口；
4. 区域要盖住整行文字：y 起点对齐文字顶，高度留足（`400x20` 常读成乱码，`400x32` 正常）；
5. 读的目标是整块窗口（含标题栏）时用 `probe --space window --region ...`，但 `--capture print` 不能配 `--space window`。

## 装完 `KeyMouse` 不能全局用

**症状**：`KeyMouse doctor` 在安装目录里能跑，换个目录就提示找不到命令。

**为什么**：安装程序只把命令行放进 `<安装目录>\cli\`，**不往 `PATH` 里写**——它不想悄悄改你的环境。

**怎么办**：把那个目录加进用户 `PATH`，然后新开一个终端：

```pwsh
[Environment]::SetEnvironmentVariable(
    'Path',
    [Environment]::GetEnvironmentVariable('Path', 'User') + ';' + "$env:LOCALAPPDATA\Programs\KeyMouse\cli",
    'User')
```

只想用一次就只改当前会话：`$env:Path += ';C:\你的安装目录\cli'`。
